# Migration

Input: agreed target/map, sufficient baseline and execution authority. Output: applied organization, validation evidence and explicit deviations. Apply root principles; unavailable filesystem access requires executor instructions, not a claim of completed migration.

## Establish the baseline

Verify the affected state against inventory, including unrelated edits and immutable sources. Obtain targeted evidence for material drift before dependent changes. Preserve enough origin information to reconstruct significant moves; use Git-aware operations where useful for traceability.

## Execute the map

Perform only specified actions: create directories; move/rename; implement defined merges/archive/reference/exclusions; update required relative references; adjust `.gitignore` or Git LFS only within the agreed plan; create required records.

Do not invent categories, hide unclassified files in miscellaneous storage, rewrite content for convenience, delete uncertain material, broaden scope or silently alter the target. For unplanned material cases, suspend affected execution and report the decision needed. Do not discard unrelated changes or accepted history.

## Validate

Compare final state with baseline and map:

- expected material is present and intended actions occurred;
- no unexplained disappearance or unintended duplication;
- required references resolve and identifiers/provenance remain traceable;
- Git/LFS and ignored/generated-file behavior match the plan;
- unresolved/deferred items remain as specified;
- cloud restrictions were respected.

Investigate discrepancies. Preserve a concise before/after record where the root completion rule requires it. Distinguish actual checks from unavailable verification.

## Handoff

Report applied actions, deviations, actual validation/results, remaining blockers and intentionally unperformed actions with reasons. Supply evidence for review; mechanical completion does not establish that structural ambiguity was resolved.
