# Inventory

Input: defined scope and accessible physical state. Output: sufficient evidence for classification/design, with uncertainty explicit. Apply root principles and cloud restrictions; this operation makes no organizational changes.

## Discover

Inspect the actual current filesystem or permitted metadata surface. Collect applicable:

- directory structure, paths/names, formats, sizes and useful timestamps/metadata;
- project/component boundaries and obvious file groups;
- Git tracking, LFS, ignored/untracked files and divergence between repository and local accumulation;
- large/binary files, temporary/generated artifacts, likely duplicates and competing versions;
- external references, cloud placeholders and broken/suspicious paths.

Start with paths and metadata. Read local content only where needed for reliable classification; do not transform it for convenience. Hash only for a concrete identity/duplicate question, not every file by default.

## Resolve targeted gaps

If evidence is insufficient, inspect the specific question: compare candidate files, read a manifest, identify generated output, verify binary identity, locate path references, or investigate a particular origin/rename in history. A follow-up request does not authorize migration or broader discovery.

## Report

Separate observations, reliable mechanical classifications, suspected relationships and unresolved roles. Identify competing current versions, ambiguous duplicates, unknown origin/ownership, contradictory names/locations and inaccessible cloud objects. Distinguish current, historical, source, derived, reference and temporary material only where evidence supports it.

Record scope, revision or relevant state, evidence pointers and access gaps so design can proceed without rescanning everything. Request targeted evidence rather than inventing roles.
