# Review

Input: baseline inventory, agreed target/map and actual migration evidence. Output: structural findings, material deviations and remaining decisions. Apply root principles; load missing evidence through targeted inspection.

## Compare

Check the actual result against the agreed design:

- expected material survives; important data was not lost;
- no unintended competing source of truth was created;
- provenance and required current/history boundaries remain understandable;
- names, roles and area boundaries match the design;
- unresolved cases remain explicit rather than arbitrarily classified;
- execution did not silently invent structural decisions;
- preservation, references, storage and cloud checks have supporting evidence.

Review both mechanical correctness and whether the design resolves the stated problems. Passing move/count checks alone does not demonstrate lower ambiguity. Do not repeat verified checks without a new discrepancy or evidence gap.

## Resolve deviations

Distinguish harmless implementation detail, a necessary discovered exception, and material structural deviation. The latter two need an explicit decision before acceptance; a review request does not supply it. Route correction instructions to migration or structural changes to design, preserving baseline and prior decisions.

Report verified outcome, evidence limits, unclassified items, disputed duplicates, unknown current versions, provenance gaps, external dependencies and deferred decisions. A successful restructuring may retain explicitly unresolved material. Project workflow owns acceptance and publication under existing authorization.
