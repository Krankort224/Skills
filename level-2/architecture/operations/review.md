# Review

## Inputs

Use the design/visual artifacts, brief and accepted baseline, requested stage, requirement sources and calculation/execution evidence. Assess the actual artifact rather than only its creator's description.

## Procedure

1. Establish the review boundary and evidence available. Do not redefine the brief to fit the delivered design.
2. Check function, program/area definitions, adjacency, circulation, composition, contextual fit, facade/material intent and coordination to the requested stage using only relevant references.
3. Check fixed constraints first. Identify contradictions, unsupported dimensions, incomplete user journeys and conflicts between drawing, schedules and narrative.
4. Trace requirement claims through [requirements](../references/requirements.md). Unknown jurisdiction/source applicability is an open finding, not an automatic rejection of independent concept work or a compliance pass.
5. Inspect requested visual artifacts through [visual delivery](../references/visual-delivery.md); verify geometry/labels/relationships and stated precision, not only file existence or export success.
6. Inspect calculations against [their contract](../references/calculators.md). Verify data, method limits, actual run evidence and interpretation. Require an independent check where a material decision depends on uncertain output.
7. Return prioritized actionable findings with location, cause/consequence, evidence and correction. Preserve accepted decisions and distinguish blockers from refinements.

## Result

A clear review outcome with supported findings, retained strengths, corrections and unresolved evidence. Review does not accept/close an Issue or authorize model changes; those actions follow their applicable task contracts.
