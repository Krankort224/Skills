# Page composition and repair

## Select an archetype
Choose from actual content, not a universal layout:
- narrative report: single text measure, clear heading ladder, occasional comparable-data table;
- technical report: single text measure with dense tables/figures and optional landscape sections;
- project portfolio: project heading, factual metadata, work narrative and integrated graphics, possibly borderless layout tables;
- proposal: title/profile, decision or offer, evidence, comparison and next steps;
- academic: conservative hierarchy, native formulas, citations and consistent figure/table numbering.

A source template may deliberately omit cover, TOC, repeating headings or header/footer. Preserve that decision unless the user requests redesign.

## Budget the page
Compute usable width from page width minus margins and cell padding; compute usable height from page height minus margins and header/footer occupancy. Size figures using both limits. Page count is a consequence of current content, not a constraint inherited from an outdated template.

Use deliberate breaks for chapters or designed portfolio spreads. Allow ordinary paragraphs to flow. Never combine whole-page cantSplit rows with content taller than a page. Before reducing type, try a wider column, a full-width row, moving a complete block, or an additional continuation page.

## Repair decisions
| Visible failure | First correction | Avoid |
| --- | --- | --- |
| A heading alone at the bottom | keep-with-next or a deliberate new section page | empty paragraphs to push it |
| Large blank gap before a table | split by complete records; relax whole-table keeping | shrinking all body text |
| A dense column beside unused space | revise widths or redistribute complete blocks | rewriting claims to fit |
| Caption stranded from image | pair the two paragraphs | keeping the whole chapter together |
| Tall technical drawing unreadable | enlarge it or share the page with concise related text | stretching its aspect ratio |
| Word-generated blank page | inspect section type, breaks and trailing table paragraph | deleting random section XML |
| Text clipped inside a cell | automatic height, proper padding and line spacing | exact row height |
| A long continuation repeats project heading | retain one semantic heading and sensible continuation | duplicate TOC entries |
| Interface screenshots dominate page | reduce to legible scale and group with relevant explanation | extra image-only pages |
| Too many bold blocks | reserve strong emphasis for hierarchy and key data | erasing source emphasis indiscriminately |

## Reading order
Check XML order and visual order together. A page that looks balanced may read poorly when its cells interleave content. Put metadata near its project title, role distinct from work, captions near graphics. Lists distributed between cells must split only at complete items.

## Keep meaningful content
For a comprehensive assembly, enumerate source blocks and prove coverage. For an explicitly condensed document, maintain a source-to-output selection map and justify omissions outside the artifact. Never silently condense because the template originally had fewer pages.

## Density
Inspect every page at full size. Use whitespace to separate groups, not to manufacture elegance. A title page with three lines may be appropriate for a formal submission but wasteful for a portfolio. Avoid both uninterrupted walls of text and excessive fragmentation into small boxed pieces.

## Image quality
Measure the effective printed size. Large plans may need full width; tiny interface text needs a more generous size. Keep real source graphics even if their aspect ratios differ from old placeholders. If a drawing contains illegible details at the permitted size, adjust composition or identify the limitation rather than claim it is readable.
