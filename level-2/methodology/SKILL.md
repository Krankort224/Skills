# Methodology

Start at the requested result. Use an existing observation, experiment, inventory or agreed map. Revisit earlier work only when a missing fact could change the answer or action.

| The user needs to… | Start here |
| --- | --- |
| Explain a discrepancy or choose a check that separates possible causes | Investigate · [Diagnose a discrepancy](operations/investigate.md#diagnose-a-discrepancy) |
| Find comparable work and decide what transfers | Investigate · [Compare prior work](operations/investigate.md#compare-prior-work) |
| Develop a procedure from scratch, compare ways of working, or decide whether a proposal warrants a change | Investigate · [Design or evaluate a working method](operations/investigate.md#design-or-evaluate-a-working-method) |
| Draw a conclusion from measurements, calculations or completed trials | Investigate · [Interpret existing evidence](operations/investigate.md#interpret-existing-evidence) |
| Establish what is present or identify competing versions | Organize · [Inventory existing material](operations/organize.md#inventory-existing-material) |
| Decide where existing items belong and map old locations to new ones | Organize · [Design the structure](operations/organize.md#design-the-structure) |
| Carry out an agreed file or repository migration | Organize · [Execute an agreed migration](operations/organize.md#execute-an-agreed-migration) |
| Determine whether a reorganization preserved the material and solved the original problem | Organize · [Review an existing result](operations/organize.md#review-an-existing-result) |

For a numerical or engineering question, go directly to [model verification](references/models.md) when the conclusion depends on model assumptions, implementation or numerical credibility. Use [experiment design and evidence](references/experiments.md) for controls, execution, handoff and reproducible results. Its [evidence record](references/experiments.md#evidence-record) defines the status fields.

A proposal, memory, or successful workaround can supply evidence when the task calls for evaluating a method. A request to list records, locate an existing instruction or carry out established domain work can finish with that result.

## Authority and access

Work within the project's authority, storage and acceptance rules. Analysis yields a finding or proposed change. An agreed map and existing execution authority permit migration. Keep inaccessible checks explicit and specify the evidence a capable executor would need.

Investigations may use text and metadata available through authorized sources. For cloud-file inventory use permitted listings and metadata. Downloading, exporting, synchronizing or otherwise materializing cloud-file contents locally requires separate, explicit user authorization. Reuse supplied evidence and continue independently supported work.

## Optional forms

Use existing project documents when they suffice. For a reproduction or handoff, adapt the [evidence map](templates/evidence-map.template.md), [experiment](templates/experiment.template.md), or [result](templates/result.template.md). When installing a local copy, replace these links with the project's adopted documents or a description of where results belong. Original templates stay in the shared source. The [source record](references/method-evaluation-sources.md) preserves the origins of adapted material.
