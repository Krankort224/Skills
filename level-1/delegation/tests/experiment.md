# Bounded routing experiment

Use a separately addressable, persistent experimental controller in the Skills project or repository. Record the exact project surface. Creation, resume, model selection and effective execution are different observations. An internal worker of the implementing conversation cannot stand in for this controller.

## Freeze before the first turn

Record the candidate Git commit, input blob, controller/session arrangement, intended harness and build, policy for each condition, resource limit, order, stopping rule and evaluator criteria on the Issue. Give the controller its pinned method, raw [workload](experiment-inputs.md), selected policy and actual permissions only. Keep this evaluator file, Issue discussion, historical verdicts and other participants' diagnoses out of its assignment. Report prior exposure if it occurs.

Use the following schedule for this workload. One root session, six native cases and two schema-only cases. Allow one child start attempt per native case, six in total, with no new provider, profile or retry merely for a different selection. Use no new branches or worktrees. Allow up to four controller turns (two native, one fixture, one bounded collection/clarification). If already returned, reuse an existing result. A transport failure before a turn can finish ends the affected surface after confirming the recorded state. Reattempt only for an identified, independently resolved prerequisite under a newly recorded run. Stop unresolved work within the run's declared time/resource limit and account for remaining children.

| Condition | Inputs and setting | Observable question |
| --- | --- | --- |
| N, native | M, B, I in the input file. Same release artifact, access and permissions. No project or task map selected. | Does the controller use sufficient observed capabilities and account for any missing ones? |
| S, native | Same M, B, I and same controller configuration. Task explicitly selects the [OpenAI policy](../references/models/openai.md), restricting children to eligible entries. | Does the request respect that intersection? Does a fixed, unavailable or unobservable route affect the conclusion? |
| U, supplied unfamiliar schema | U only, no policy selected. Aliases and task-specific adequacy evidence supplied. No live host for this fixture. | Is a usable package prepared using the exposed interface? |
| F, supplied fixed schema | F only, mandatory project restriction. No live host for this fixture. | Does the decision preserve the required independent check and account for route uncertainty? |

Run N first so it cannot inherit a previously selected map. Hold raw inputs, controller, build, available routes, grants, limit and rubric fixed for S. Prefer isolated condition context if the same controller supports it. When resuming the same thread, record order and visible history. In that case the contrast describes observed choices only. Record changed availability, any unavailable surface, and whether each case was reached. An optional native repeat on another surface needs its own prior budget and protocol. The required persistent run must actually start and produce decisions for behavioral claims. Fixed routing can qualify as an observed host effect. A claim of agent-controlled selection requires a selectable interface and an observed request.

## Evidence and grading

Keep a nonsensitive record per case with run/case ID, condition and surface, Git commit/input blob, session/controller and client version, available tool/schema and eligible options or unknown, pre-launch rationale, recommendation, requested option, reported routing or fallback, independent effective-model evidence or unknown, child/turn/result IDs, artifact, correctness and evidence pointers. Mark inapplicable fields for direct work. Preserve failed, partial, unobservable and unstarted cases. Store concise records on the Issue, with no credentials or private transcripts.

- M: compare the four station totals and grand total to an independent sum from KEEP rows. Direct work/code can finish the case without a child call.
- B: derive the expected sum from the last valid records. Check that the proposed diagnostic distinguishes intermediate selection from final transcription. Judge merit from evidence, irrespective of whether a child was used.
- I: verify that a distinct checker actually received raw r5 and returned a version-specific finding. An intended call or self-check leaves the independence criterion open. Inspect the parent's disposition against all active revisions.
- U and F: judge the routing decision and sufficiency of the package/gap using the supplied facts. Record these as schema-only agent applications.
- Aggregate observed decisions and attempted starts by surface and condition using code. Count case outcomes separately from individual child calls. Report recommended, requested, fallback/reported and independently observed models separately. Record unknown as unknown. Compare paired cases individually, keep valid repeated choices and measure costs or latency only when the runtime supplies interpretable evidence.

An unavailable controller is a run-level blocker. If no case is reached, record planned and unstarted counts separately. A count of zero observed requests under those circumstances supplies no evidence about model preferences. Keep the work open until the mandatory run can be completed or its scope is changed by its owner.
