# Kimi Code CLI delegation

Official Moonshot AI documentation checked 2026-11-22 (Europe/Moscow). This profile covers the `Agent` tool in Kimi Code CLI and its related task controls. A Kimi model served through another host has that host’s tools. Evidence is documentation only, with native behavior untested in this environment. Check the installed CLI version, session tool schema, effective configuration, and permissions before dispatch.

## Dispatch and routing

- Supply the assignment in `prompt` and a short label in `description`. `subagent_type` selects the worker profile and defaults to `coder`. Ordinarily the child starts with its own conversation and returns its result without importing its intermediate tool history into the caller. Release 0.39.0 documents an experimental `fork` parameter for a snapshot of the caller’s conversation. Use fresh context by default and rely on a fork only when the live schema exposes it and sharing is appropriate. [Agent reference](https://moonshotai.github.io/kimi-code/en/reference/tools.html#collaboration-tools) · [Agent context](https://moonshotai.github.io/kimi-code/en/customization/agents.html#context-isolation-and-resource-cost) · [Release 0.39.0](https://moonshotai.github.io/kimi-code/en/release-notes/changelog.html#_0-39-0-2026-08-27)
- Without a configured `[secondary_model]` pool the child inherits the caller’s model. One configured entry pins it. With two or more entries, `Agent.model` selects a configured pool alias and omission uses `default_model`. An alias outside the pool is rejected. Read the advertised choices and authorized configuration before selecting. [Subagent model pool](https://moonshotai.github.io/kimi-code/en/configuration/config-files.html#subagent-model-pool)
- `coder` can edit and run commands, `explore` is read-only, and `plan` has no shell. The built-in profiles are leaves. Deeper delegation requires a custom profile with the effective delegation tool and an explicit allowlist permitting the next profile, within the approved tree. Custom profiles can restrict tools and children, and parent permission rules propagate. `Agent` exposes no per-child workdir or worktree selector. Remote subagents inherit the parent’s execution environment. Verify actual paths and file access, and keep writes disjoint. [Agent profiles and permissions](https://moonshotai.github.io/kimi-code/en/customization/agents.html) · [Agent reference](https://moonshotai.github.io/kimi-code/en/reference/tools.html#collaboration-tools) · [Remote environments](https://moonshotai.github.io/kimi-code/en/guides/remote-environment.html#use-a-remote-environment-over-ssh)

## Completion and recovery

- `Agent` waits in the foreground by default. `run_in_background` returns a task ID, with completion delivered back to the main agent. Use `TaskOutput` for status or `WaitFor` when the current turn needs the result. A wait timeout leaves the task running. In user-enabled swarm mode, `AgentSwarm` can launch or resume a batch and waits for the aggregate result. Check active timeout and print-mode completion settings on the host. [Collaboration tools](https://moonshotai.github.io/kimi-code/en/reference/tools.html#collaboration-tools) · [Background task tools](https://moonshotai.github.io/kimi-code/en/reference/tools.html#background-tasks) · [Task configuration](https://moonshotai.github.io/kimi-code/en/configuration/config-files.html#task)
- `TaskStop` stops a background child task under its approval policy and returns the agent ID and any incomplete text. Use `Agent.resume` with that agent ID and a fresh `prompt` to continue the instance. Omit `subagent_type` on resume. The instance keeps its model. Check settled status and artifacts before reassigning writes. [Background task tools](https://moonshotai.github.io/kimi-code/en/reference/tools.html#background-tasks) · [Agent reference](https://moonshotai.github.io/kimi-code/en/reference/tools.html#collaboration-tools)
