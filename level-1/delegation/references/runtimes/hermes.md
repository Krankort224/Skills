# Hermes Agent delegation

Use this route when Hermes exposes the model-facing `delegate_task` tool. Official Nous Research documentation rechecked 2026-11-24. This profile is documentation evidence only. No local installation, enabled backend, native run or provider identity was verified here. Check the live schema, active session/profile and permitted effects.

## Dispatch and routing

- Supply `goal` and `context` for one child, or a `tasks` array with the package for each child. Each child starts a fresh conversation. A resolved workspace can contribute project instructions. The parent receives a summary and verifies the reported artifacts. [Task arguments](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#single-task) · [Child context](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#how-subagent-context-works)
- The built-in `default` backend can fix the child model through `delegation.model` or inherit the parent's model when that setting is absent. Its provider or endpoint comes from delegation configuration or the parent. The tool has no per-task model parameter on this backend. Record the fixed or inherited route and evidence from the actual host. [Built-in routing](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#model-override)
- The official `advanced-delegation` plugin requires Hermes 0.22.5 or newer. When an installed, authorized backend exposes them in the session schema, `model_map` accepts the configured `option` alias and `profile_routes` accepts the configured `profile` alias. Omitting selection uses that backend's configured default or the parent route when no default exists. Unavailable backends and unsupported or unresolvable selections are refused. The available aliases are controlled by configuration. They can implement a [selected policy](../model-selection.md) when the correspondence and limits are known. [Delegation strategies](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#delegation-strategies-delegationbackend) · [Advanced Delegation](https://hermes-agent.nousresearch.com/marketplace/advanced-delegation)
- A model route uses its own `fallback_providers` when set, including an empty list to disable fallback, or inherits `delegation.fallback_providers`. A profile route uses that profile's fallback chain and can change credentials, skills and terminal policy. Confirm those effects are within the assignment. Where present, inspect the result's `route` and its `fallback_activated` field to determine the harness route. Verify provider-side identity separately when material. [Route metadata and fallback](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#delegation-strategies-delegationbackend)
- Children generally inherit enabled toolsets with child restrictions and have a separate terminal session in the shared workspace. A child is a `leaf` by default. Descendants require `role="orchestrator"`, effective `delegation.orchestrator_enabled`, sufficient `delegation.max_spawn_depth` and an assignment grant. Opt-in Git worktree isolation is local-terminal-only, can create branches, and can fall back silently to a shared checkout. Verify the actual writable location before relying on isolation. [Tool access](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#inherited-tool-access) · [Depth](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#depth-limit-and-nested-orchestration) · [Worktrees](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#worktree-isolation)

## Delivery, continuation and settlement

- With later delivery, a top-level call returns a handle and posts results between parent turns. An orchestrator child waits for its workers. Stateless request/response endpoints can fall back to synchronous execution. Record the handle and child IDs when exposed. A durable completion record can outlive its delivery. A restart can leave an unfinished attempt `unknown`. Check its effects before replacement. [Batch delivery](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#batch-mode-details) · [Session lifetime](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#lifetime-and-durability)
- Where exposed, `delegate_task(action="list")` reports active and queued children. For a running `subagent_id`, `steer` queues a `message`. `stop` requests interruption by ID and can return a partial result. `continue` uses `subagent_id` and a new `message` to restore a finished or resumable transcript and route when supported. It preserves the child/session identity and starts a new attempt with a new completion handle. The model-facing controls are scoped to the owning spawn tree. A stored child stays within its owner's delegation context. [Model-facing controls](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#from-the-parent-agent-model-facing)
- Session controls such as `/stop` and explicit close or reset can stop running delegations. Stopping the parent's current turn or detaching a client can leave background work running. Check the session type and confirm settlement. [Session lifetime](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#lifetime-and-durability)
- The gateway's opt-in `delegation.auto_resume` can leave a limit-stopped writer `waiting_to_resume`. Its write area remains assigned. A replacement launch leaves the queued resume active. Wait for settlement or cancel the queued child with `delegate_task(action="stop", subagent_id=...)` where authorized and confirm the resulting state before overlap. [Automatic resume](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation#automatic-resume-delegationauto_resume-opt-in)
