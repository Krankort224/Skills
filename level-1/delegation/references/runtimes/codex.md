# Codex subagents

Use this profile when Codex exposes its native subagent tools to the current agent. Check the live tool schema and permissions before dispatch. The names below come from the OpenAI Codex CLI `0.172.0-alpha.2` source. Exposed fields, defaults, model eligibility, depth and concurrency can differ by client, version, configuration and session. A host that exposes its own collaboration functions requires its own live tool contracts.

## Model-facing tools

| Operation | `multi_agent_v1` namespace | V2 functions when exposed |
| --- | --- | --- |
| Start a child | `spawn_agent` accepts `message` or `items`, with optional `fork_context` and, where exposed, `agent_type`, `model` and `reasoning_effort`. By default it starts with the task input and returns an `agent_id`. `fork_context=true` copies parent history and inherits its agent type. | `spawn_agent` takes `task_name` and `message` and returns a canonical task name. `fork_turns=none` omits parent history. The tagged schema defaults to `all`. Supply an agent type or model/effort only when the active schema and permissions expose that choice. |
| Continue or redirect | `send_input` takes `target` and `message` or `items`. It queues the input by default. `interrupt=true` interrupts current work before handling the input. `resume_agent(id)` reopens a previously closed child so it can receive input. | `send_message(target, message)` queues a message without starting a new turn. `followup_task(target, message)` starts a turn for an idle child or delivers the update to an active one at a permitted boundary. |
| Observe and collect | `wait_agent(targets, timeout_ms)` can return a final status and the child's result. Use the actual status and result or delivered notification. An empty timeout result leaves the work pending. | `list_agents` reports the current tree. `wait_agent(timeout_ms)` reports mailbox activity, interruption by user steering, or timeout. Read the associated message or result separately. |
| Stop work or release capacity | `close_agent(target)` requests shutdown of the child and open descendants and returns the previous status. Completed children can occupy slots until closed. | `interrupt_agent(target)` interrupts the current turn and returns the previous status. The target remains available for a message or continuation. |

Use the identity returned by the active tool. A child thread remains part of its parent session tree even when it has a durable ID or can be reopened. A fresh task context limits inherited messages. Verify filesystem scope, inherited instructions and permissions separately. Before reassigning writes, confirm settlement of the previous turn, queued inputs that could trigger work, and any external effects relevant to the write scope.

## Routing and evidence

- The requested model and reasoning effort are separate controls. Codex can inherit the parent values, apply configured subagent defaults, or accept explicit values in the live spawn schema. A custom agent file can take precedence for the settings it specifies. When an explicit or configured model is selected without an explicit or configured effort, the selected model's default effort may apply. Existing roles and defaults are runtime settings. They do not select a project model map or authorize configuration changes.
- When the live schema withholds override fields, use the known inherited or configured route only if it meets the task. Record that routing mode, or record unknown when it cannot be established. When overrides are available, check the permitted model and effort combination and retain any refusal or fallback alongside the original request.
- App Server JSON-RPC is client-facing. `thread/start` and `thread/resume` address Codex conversations, `thread/read` reads thread data, and `turn/interrupt` acts on a specified thread and turn. Those methods are distinct from model-facing child tools. A client-visible `collabAgentToolCall` item can associate a call with sender and receiver thread IDs. Inspect the item's phase and exact version before treating its model field as evidence of a request or resolved child configuration.
- `thread/read` can expose lineage and the configured or last persisted `model` and `reasoningEffort`. These fields support identifying the harness configuration. To establish actual execution routing, require an independent run-level trace that identifies the executed model for the child and turn. Mark that field unobservable when only tool parameters, status or configured labels are available.

The versioned [model-facing schemas](https://github.com/openai/codex/blob/rust-v0.172.0-alpha.2/codex-rs/core/src/tools/handlers/multi_agents_spec.rs), [child settings resolver](https://github.com/openai/codex/blob/rust-v0.172.0-alpha.2/codex-rs/core/src/agent/child_config.rs), [v1 spawn handler](https://github.com/openai/codex/blob/rust-v0.172.0-alpha.2/codex-rs/core/src/tools/handlers/multi_agents/spawn.rs) and [v2 spawn handler](https://github.com/openai/codex/blob/rust-v0.172.0-alpha.2/codex-rs/core/src/tools/handlers/multi_agents_v2/spawn.rs) establish the implementation details. See OpenAI's [subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) and [App Server](https://learn.chatgpt.com/docs/app-server) documentation for client and configuration behavior. The CLI's generated App Server schemas describe the client protocol and its metadata. Source and schema inspection establish interface semantics. Verify live tool exposure and completed routing in the executing session.
