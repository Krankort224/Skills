# Refinement decision cases

These synthetic fixtures exercise observe/generalize/refine and placement. Their inline methods and observations are fixture sources, not claims about production skills or native runs. Their source revision is this file's reviewed artifact. Use no real project edits to enact them.

Start from the learning root and load only the operation/resources the requested action needs. For B01/B02, return a compact candidate with evidence, mechanism, scope/exclusions, owner/change, protected behavior, authority and planned original/transfer/regression checks. For other cases, return the appropriate result without manufacturing a candidate. The optional improvement template supplies no authority.

## Inputs

### B01 — Correction of a positional merge

The complete fixture method `export/operations/merge.md` promises to merge records by stable unique `id`, preserving master order. It requires rejecting duplicate IDs or unequal ID sets, then instructs zipping the two sequences by position and taking master quantity plus lookup label. That instruction was followed on master `[(N,3),(S,7)]` and lookup `[(S,South),(N,North)]`. Output was `[(N,3,South),(S,7,North)]`; the user correctly points out that each label belongs to its ID. Inputs, method and output are available. This is the first such correction. The task permits proposing/testing a fixture-method change; no replacement has been tested.

### B02 — Useful sensitivity technique

The complete fixture comparison method `comparison/operations/rank.md` evaluates higher-is-better criteria on a fixed comparable 0–10 scale at declared weights and selects the highest score. For two alternatives A=(9,3), B=(5,8), it used weight w=0.6 on the first criterion and 1-w on the second. The task asks whether that preference remains defensible while w ranges from 0.45 to 0.65. A task-authorized exploration formed score functions A=3+6w, B=8-3w and found equality at w=5/9: A wins at 0.6, B at 0.5. Arithmetic was checked. The existing method contains no sensitivity branch. This useful result establishes the nominal choice is not robust across the stated range; it does not establish a preferred new weight, feasibility of each alternative, or nonlinear/multi-parameter behavior. The fixture-method owner is in scope.

### B03 — Routine work and skipped instruction

The agent correctly handled five ordinary merges under an adequate method. On a sixth task it skipped the existing unique-ID check and the user corrected the resulting duplicate output. The check is accessible and unambiguous; no evidence shows a method or navigation gap. The task asks only to correct that output.

### B04 — Repeated project configuration

Three projects of the same client require a local display label and confirm it at their requirement owners. Shared guidance already delegates labels to project requirements. Only the current project reference may be updated. Someone suggests putting the client's value in the shared root because it recurred.

### B05 — Read-only destination

Use B01's evidence, but the assignment is a read-only review of the actual shared owner. Creating a writable project copy of the method or publishing a new Issue is technically possible. Neither is authorized. Return the most useful result within that assignment.

### B06 — Unknown actual method

A summary says a merge ignored stable IDs, but the actual used revision, prescribed step, inputs and output are missing. Current source inspection finds a correct keyed procedure. The summary author confidently calls this a missing method branch. The task has no access to the original run.

### B07 — An existing mechanism with a broken route

In a different fixture, the comparison reference already contains an adequate sensitivity method, but the operation points to a deleted path. The current method location and broken link are verified. The task permits repairing this route. There is no evidence that the sensitivity method is inadequate.
