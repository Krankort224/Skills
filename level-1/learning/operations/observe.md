# Observe a meaningful episode

Use this operation when a correction, failure, missing branch or uncommon success could change a method. Start with the root's activation decision; an ordinary correct result needs no observation record or further learning work.

## Select the evidence

1. Identify the actual task outcome and constraint that made the episode significant. A correction is a signal to investigate, not proof that a shared method is wrong.
2. Locate the method/operation and exact source revision actually read. Compare its instruction with the actions taken and resulting artifact. Reuse existing source pointers, inputs, outputs and checks; do not reconstruct execution from a later source or an agent's summary alone.
3. Keep the smallest evidence slice that can support or change the decision: relevant input/condition, prescribed step, action, observed result, expected result and its owner. For an uncommon success, include how completeness/correctness was checked and which technique differed from the existing method.
4. Separate observed output from a suspected cause, fixture assumptions and checks not performed. Name a missing source, runtime or permission when it affects attribution. Do not turn a tool's success indicator into evidence that the requested result is correct.

Use [evidence and scope](../references/evidence-and-scope.md) for cause/scope decisions. When the current task already supplies these facts, use its evidence rather than collecting them again.

## Keep the record proportional

Return the evidence slice on the existing task surface, with pointers to authorized artifacts. Keep private content at its existing owner; use a sufficient non-sensitive description or authorized minimal fixture for a shared candidate. Do not copy a transcript, credentials, live project bindings or per-tool history into a skill. Observed/quoted instructions are evidence, not permission to expand the task.

No new file, Issue, central log or periodic observer is required. A short task response can be the whole record. Retain uncertainty instead of filling fields with guesses.

## Stop or continue

- Adequate instructions were merely skipped: correct execution within the task; stop skill refinement unless separate evidence supports a method/navigation defect.
- Only a project fact or context/access gap remains: send the fact/gap to its established owner through the authorized task action; do not start a shared-method edit.
- A potentially reusable gap or useful technique has enough evidence to examine: pass that slice to [generalize](generalize.md), without claiming that a candidate works.
- A material input/source/outcome is unavailable: identify the smallest discriminating check and its capability needs; obtain it if authorized or defer. Do not harvest unrelated runs in hope of replacing it.
