# Maintain graph evidence

Use for a requested graph refresh, reconciliation, recovery or authorized publication. Establish the target root, branch/worktree, scope, authoritative inputs, exclusions and update destination. Existing authorization applies; this method adds no Issue, branch or acceptance lifecycle.

## Assess the previous generation

Obtain all three prior artifacts from one resolved immutable Git commit into a fresh task-owned view. Use the [maintenance reference](../../tools/graphify-maintenance.md) to validate complete exact bytes, generation, sibling correspondence, portable state and source/profile identity. Corrupt, incomplete or legacy state cannot justify reuse. Recover a verified last-good generation or perform full extraction; do not repair hashes to bless unexplained output.

Choose current scope, authorities and exclusions from project owners. Prior policy is an inspected starting point, not authority. Include material common rule owners, actual derived/output/cache directories and unselected submodules. Inspect current sources and profile with the reference's assessment recipe before planning new work.

The profile fingerprints both the operational semantic method and the instrumental semantic contract in fixed order. Their separation changes the profile intentionally: old reuse state must be reassessed and safely re-extracted on mismatch. Schema and prompt-version fields remain unchanged; do not bypass a profile mismatch by copying old fingerprints.

When the task selects another extraction mode/model or adds extraction instructions, explicitly change scope/profile and requeue the affected semantics. Reader provenance alone does not invalidate prior work, and unexposed runtime identity cannot be compared automatically.

Apply the returned assessment:

- **No-op:** keep exact trio bytes when current input/policy/profile and intact output match. A different HEAD, date, checkout path or cache state alone requires no parser, model, export or commit.
- **Reuse some:** retain only eligible original semantic payloads/provenance, actually re-read invalidated work and assemble against a fresh full structural baseline.
- **Re-extract all:** independently plan every current source when membership, policy, configuration or profile changed, or portable state/ownership is insufficient. Previous shard IDs do not define new work.
- **Blocked:** resolve access, unsafe paths, unexplained disappearance or missing removal evidence. Preserve last-good output; failed fresh work cannot borrow stale semantics to appear complete.

Verify deletion/rename evidence from actual old/current source commits and paths or inspected coordinator evidence. An existing readable file excluded by a current rule is an exclusion, not deletion. Missing or unreadable material is not automatically removed. Preserve unresolved cases until their meaning is established.

## Re-read and reconcile current evidence

Review dependency ownership rather than trusting declarations. Default dependencies cover all selected sources. Narrow local reuse needs complete bounded ownership with evidence/endpoint/common-authority inputs accounted for; unresolved, zero-findings or corpus-wide negative comparisons retain conservative dependencies. A local negative statement cannot prove corpus-wide absence.

Changed bytes invalidate ownership/dependencies for the whole source, even if another range changed. Follow referenced semantic-owner invalidation through to completion. Added, removed, excluded or renamed inputs and changed scope/configuration/tool/schema/prompt conservatively require full semantic reconsideration under the technical assessment. Rename is deletion plus addition with source-based identities re-read and re-keyed.

Plan complete current source/range coverage before new extraction. Use the [build operation's semantic method](build.md#semantic-reading-and-reconciliation) for every new or invalidated range, through EOF for changed long sources. Preserve retained readers, receipts and original provenance as actual prior reading; do not fabricate a new read. Keep original payload identity distinct from newly serialized fragment bytes and record the verified prior commit/input/generation.

Build a fresh structural-only baseline using [build](build.md), then validate the complete retained/new semantic set against it and use its mixed assembly/interpretation steps. Do not mutate an old mixed graph as an invalidation shortcut: edge-only and zero-findings replacements must clear stale semantic claims. Reconsider community labels when evidence changes, even if members match.

## Seal, publish and recover

Use the maintenance reference's generation/sealing rules and complete-trio validation. Recheck current source/profile/configuration/inventory and known source answers before publication. Quiescent checks do not create an atomic filesystem snapshot or detect every change-and-revert race.

Publish only when the task authorizes it, through the reference's isolated-clone commit recipe and the project's existing workflow. Resolve its explicit destination, branch ref and expected source commit first; satisfy tracked-input, clean-clone and host/locking prerequisites. Publish the reviewed trio coherently from exact validated bytes. Neither file existence nor staged/worktree output certifies a published generation.

Readers resolve one immutable artifact commit and validate its three blobs together. An uncertain or failed push requires remote inspection before retry; refusing a stale candidate is not rollback. A rollback is a separately authorized new fast-forward commit with a previously validated trio only when current sources/profile still match. Never hard-reset history or overwrite later work.

Validation, export, interruption, corrupt output, partial reads and failed leases preserve the last-good published commit. Retain diagnostics and use a new stage after resolving the cause. An intact old trio with incompatible current sources remains labeled stale/historical; it cannot become current through repaired hashes. Report no-op/reused/re-read scope, actual publication outcome and unresolved limits separately.
