# Build graph evidence

Use when the task explicitly requests initial structural or semantic graph construction. This operation prepares fresh staged evidence from the selected sources. Publication follows the project's existing authorized workflow. A missing graph does not require construction for ordinary project understanding.

## Select and prepare the corpus

Resolve the canonical source root, branch/worktree, scope, authoritative sources and task-owned staging destination. Select formats explicitly within the [runtime and format scope](../../tools/graphify.md#source-and-supported-profile).

Choose explicit exclusions for generated references/graphs, native memory output, staging/cache, secrets and unselected third-party/submodule inputs. Adapt actual paths to the project. Account for unsupported, sensitive, unreadable, ignored and pruned material without claiming an exhaustive descendant inventory for excluded trees. Do not initialize submodules, convert unselected inputs or follow symlinks implicitly.

Use the technical profile's [environment preparation and check](../../tools/graphify.md#prepare-and-verify-the-structural-environment) before the [structural recipe](../../tools/graphify-build.md#build-and-inspect-structural-evidence). Reuse a verified isolated environment; prepare a task-owned one only when needed and authorized. An unavailable interpreter, dependency, network or write capability is a specific preparation gap; direct-source investigation remains available.

## Build and inspect the structural baseline

Run the structural recipe with the verified interpreter, its required process environment and fresh staging/cache outside the source tree. Keep source inputs quiescent. Check selected inventory, bytes and consumed configuration before and after extraction/export. These checks detect observed changes rather than creating an atomic source snapshot.

Inspect known caller-to-callee and document-reference endpoints, source locations, extraction origin, confidence annotations, unresolved links and folded evidence against actual sources. File presence, nonzero counts and page nodes do not prove complete Markdown or semantic coverage. Report raw/built count differences and omissions honestly. Structural-only output records that no model/semantic pass was performed; its zero model counters do not measure the agent's other reading.

Stop here for structural-only construction. The recipe's bounded staged query can help inspect a known symbol; follow its returned locations to sources and do not interpret undirected context as a directional dependency path.

## Semantic reading and reconciliation

<!-- context-semantic-contract:start -->

Semantic extraction uses the active agent's actual reading and reasoning. It has no provider inference command. Use permitted agents under `delegation` when useful and available; otherwise process the same bounded plan serially. Do not infer concepts from filenames, require an invented agent interface, restart clients, alter credentials or fall back to ambient provider keys.

1. **Plan independently before collecting results.** Start from the verified fresh structural baseline and keep its root, inventory and bytes fixed. Plan every selected baseline source, including irrelevant sources with explicit zero findings. A semantic subset cannot conceal stale structural inputs. Keep plans/results task-local and outside graph artifacts. The [instrumental contract](../../tools/graphify-build.md#semantic-protocol) owns exact plan/fragment schemas, native IDs, hashing, encoding and validator limits.
2. **Bound work by actual content.** Consider bytes, density, lines, file count and host output/context limits together. Begin with a few short files and small ranges; isolate long text. Upstream suggests at most 20–25 files and about 6000 lines per chunk, with text over 2000 lines isolated; reduce these upper bounds for dense material or actual host limits. Validator ceilings are not recommended workloads. Enumerate ordered source ranges through EOF with their source identities; require complete coverage without gaps or overlaps. Preserve one source identity across slices.
3. **Read every assigned range.** Page output until the full range is visible, checking for capped, short, missing or truncated results. A hash, receipt, reported line count or successful tool call cannot establish understanding. Re-read missing parts before declaring completion. Empty sources and unrelated material still require an explicit completed negative result.
4. **Keep assignments sufficient and independent.** Give a worker scope, assigned ranges, source/authority instructions, needed exact structural IDs and the evidence contract. Keep truth-set answers outside the reader's view. Results may return as JSON in conversation; worker filesystem writes are optional. Preserve actual assigned/observable reader provenance and unknown usage. Serial reading follows the same contract without fabricated worker activity.
5. **Record findings and nonfindings honestly.** Explain each range's reading result and its reason. Findings must own an emitted record or unresolved question; empty graph arrays alone cannot substantiate them. Zero-concept, unrelated and negative findings are completed outcomes, not fabricated nodes or cache hits. Missing, failed, malformed or partial work remains incomplete. Retry only failed work, then revalidate the full independently expected result set. Incomplete work cannot replace a complete previous semantic source group.
6. **Preserve source ownership and authority.** Ground concepts in material actually read. Use stable source-owned entity identities and exact structural symbol IDs rather than labels, chunk suffixes or duplicate AST symbols. Keep rationale on the relevant record rather than inventing sentence-shaped entities. Distinguish current, superseded, observed and unresolved claims; historical conflict does not override the current subject owner. Supporting-source reading does not silently claim ownership or complete coverage of that source's tier.
7. **Make evidence inspectable.** Every accepted semantic relation needs exact supporting source ranges and a meaningful directed relation. Primary evidence belongs within its assigned range and record location; additional sources must also have been read and planned. Inferred or ambiguous cross-source relationships need anchors for both endpoint sources; explicit references may be grounded in the referring source with an independently verified target. Optional groups need evidence for their member-source identities and must express something useful beyond pairwise edges.
8. **Apply confidence to the claim.** Use EXTRACTED for explicit evidence, INFERRED for a supported inference with its stated basis, and AMBIGUOUS for a real unresolved candidate. Follow the technical contract's encoding/rubric; scores are annotations, not calibrated probabilities. Preserve caller-to-callee direction for calls. Do not invent connections to make a graph connected, convert unrelated text into ambiguity or confuse absence of an edge with absence of a relationship. Prefer an evidence-bearing open question when the referent remains unresolved.
9. **Reconcile across the complete reading.** A later slice can reference a concept introduced earlier. Resolve endpoints against the aggregate semantic and structural identity universe. Each node has one explicit owner. Conflicting or duplicate definitions require source review and a reconciled response; first-writer wins, automatic renaming and chunk suffixes cannot resolve meaning. Re-read material sources when deciding equivalence. Preserve original returns privately for execution review and meaningful corrections without copying transcripts into project knowledge.
10. **Keep evidence layers distinct.** Mark semantic records explicitly according to the instrumental contract, including line-located evidence. Preserve independent structural, documentary and model-derived facts. Do not disguise a relation or reify an entity merely to evade a storage collision. If native assembly cannot preserve the actual independent claims, report that unsupported case. Keep original structural evidence independently owned.

Validate every expected fragment and the complete coverage/evidence ledger before native assembly. Mechanical validation establishes contract consistency, not semantic relevance or understanding; review actual answers against source truth. Native partial-success merging, sanitization or zero-filled usage cannot substitute for the selected complete-set validation route. Recorded-fragment replay is integration evidence; only a current agent's actual read is a fresh semantic pass. Fresh inference is not byte-deterministic.

## Assemble and interpret the mixed result

Follow the [mixed assembly recipe](../../tools/graphify-build.md#assemble-interpret-and-verify-a-fresh-mixed-trio) after complete semantic validation. Its first run exposes exact current community members and evidence identities without writing artifacts. Read those members, relevant source evidence and uncertainty; author short source-backed labels and rationales. Bind interpretation to both the current input/evidence and exact membership. Unchanged members alone do not justify reusing meaning after claims change. Labels do not create project facts.

Rerun that recipe with the inspected interpretation, retaining the same baseline and complete explicit fragment set. Recheck selected source bytes, paths and scoped configuration. The unsupported/omitted inventory remains the observation from structural staging; rebuild that baseline when current whole-inventory evidence is needed. An observed inventory mismatch requires fresh structural staging rather than guessed repair.

Review the reloaded JSON's semantic answers and known source relations, native direction/origin/evidence retention, coverage, interpretation and the complete JSON/HTML/report set. Preserve unknown subscription usage as unknown. Export does not prove browser rendering; use [presentation inspection](export.md) only when selected. For publication or later refresh, continue with [maintenance](maintain.md).
