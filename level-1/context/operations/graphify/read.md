# Read graph evidence

Use when a project question deliberately selects graph assistance. Begin with the question, project/branch scope and authoritative fact owner. Direct sources remain available when the graph is missing, stale, incompatible, corrupt, oversized or unhelpful; this operation does not authorize a rebuild or optional view creation.

## Select a verified input

For a published mixed generation, resolve one immutable artifact commit and obtain its complete trio in a new task-owned view. Follow the [read reference](../../tools/graphify-read.md) and its complete-trio checks; inspect current source/profile compatibility before calling claims current. Integrity checks do not establish source truth. Use the separate bounded staged query only for its known sidecar-free structural/mixed-stage conditions.

Select the verified native-library route. CLI query/path/explain can attempt file writes, and other loaders can consume optional derived sidecars. Follow the reference's process prerequisites and exact validated-dict recipe rather than assuming an apparently read-oriented command is inert. Consider whole-graph load/resource suitability separately from bounded agent-facing output.

## Choose the method that answers the question

- **Locate a concept or symbol:** inspect a bounded qualified candidate list and resolve its exact identity. Use bounded context traversal to localize sources, then verify relevant facts there.
- **Explain an entity:** inspect immediate incoming/outgoing relations, evidence/confidence and source sites. Read the cited ranges for actual meaning.
- **Find a stored directional connection:** disambiguate both endpoints, inspect the directional path and disclose native reverse-containment exceptions. Undirected context traversal is a different form of evidence.
- **Assess candidate impact:** select actual relevant relation types and depth, then verify candidate sites and canonical dependencies. Unrepresented semantic relations require direct-source search.
- **Explore themes, hubs, bridges or isolation:** inspect actual members and input interpretation. Treat rankings/components as navigation heuristics, not source authority, architecture, runtime reachability or test coverage. Do not recluster or rename during reading.

Use only needed methods. The [technical reference](../../tools/graphify-read.md) owns calls, parameters, budget behavior, direction exceptions and heuristic limits. Bound displayed candidates, node details and evidence; do not dump portable fragments or arbitrary graph metadata. If output is truncated, narrow or page the question and disclose omissions rather than inferring absence. Missing paths, edges or impact hits can reflect coverage, filters, depth or algorithm limits.

## Follow sources and answer

Verify every material conclusion at its applicable owner, preserving source scope, authority, current/historical role, direction and uncertainty. Connectivity and annotations cannot override canonical evidence. A relation's name or numeric value alone cannot establish units, callers or runtime integration. Check underlying evidence when path text omits source sites.

When comparing methods is requested, prepare direct-source control answers without graph hints and use matched questions/revisions. Record correctness, missed/false relations and actual observed retrieval effort, including failed attempts and unnecessary output. Unexposed counters remain unknown; fixture replay or shared model knowledge is not a blind benchmark. Prefer the route sufficient for the task without promised savings.

Report the resolved source-backed answer, graph input/currentness and meaningful limits. Optional rendering, exports or a combined cross-repository view use [export](export.md) only when selected by the task; reading alone creates no authority to write those views.
