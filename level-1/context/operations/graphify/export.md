# Inspect and export graph views

Use when presentation inspection, interchange or a separate combined view is requested or selected within the authorized task. Begin with one checked generation and a demonstrated purpose. Additional views do not establish currentness or replace the complete JSON/HTML/report trio.

## Select the view and destination

Keep input commit/hash/generation and limits in existing view metadata or the task result. Choose only needed formats and explicit fresh task-owned destinations outside source and the reserved trio directory. Follow the [export reference](../../tools/graphify-export.md) for exact native calls, prerequisites and ownership. Preserve input fingerprints; use one writer and inspect returned counts/warnings rather than accepting successful file creation alone.

GraphML serves interchange with its documented attribute conversions/loss. SVG serves a static illustration and requires its separate reviewed plotting environment and visual inspection. Wiki and Obsidian own generated files and may overwrite/prune content; use dedicated generated destinations and preserve human prose elsewhere. Optional output is not published implicitly.

## Inspect presentation against evidence

Check embedded HTML nodes/edges/counts and report input/coverage against the exact JSON. Follow detailed rationale, origin and evidence in JSON and sources; a node panel or report summary is not the full semantic record. Keep unknown usage and coverage qualifications visible.

When browser verification is selected, open the exact view through an allowed route and observe actual graph drawing, search, source panel, community visibility, text and zoom. Follow the reference's CDN/browser constraints. Empty canvas with correct counts is a rendering failure; unavailable assets leave HTML unrendered while JSON/report remain useful. Do not bypass browser policy or silently replace pinned assets. Stop temporary test servers afterward.

Disclose aggregation and its lost direction/parallel/internal evidence. A community summary cannot stand in for the full-evidence trio; an exporter message cannot excuse a missing HTML file. Read the visual key correctly: apparent size, color, width, dashes, opacity and selection are native presentation encodings, not measured strength or calibrated probability. Inspect SVG at the intended size and zoom for clipping, overlap and readable legends; parsed XML alone proves no readability.

Apply legend annotation only during an authorized fresh export before sealing. Do not patch a published sibling or repair hashes around unknown output. Native exporters' multi-file changes are not publication transactions.

## Create a scoped cross-repository view

Select explicit stable repository tags and pin every checked input to its immutable artifact/source commits, exact graph and generation/profile identities. Verify current source compatibility when claiming currentness; retain historical labels otherwise. Missing or unresolved provenance requires separate-source investigation rather than invented version identity.

Follow the reference's ordered prerequisites: materialize and validate inputs through the read method, bind those exact views to real Git objects, then compose only the checked bound records using the native namespace recipe. Preserve directed/parallel arcs, evidence ownership and explicit input manifests. Refuse collisions, conflicting external attributes and unsupported external-only arcs instead of dropping evidence. Shared external IDs provide navigation joins, not proof of matching dependency versions or interoperability.

Write and reload a new separate view; check full IDs, directed arcs/keys, hyperedge membership and input manifests, then recheck input fingerprints. Resolve every source by its input repository and commit. Do not infer cross-project relationships from similar labels or treat the combined view as one repository's maintenance state or a global writable graph. Follow native namespace limitations for nested references rather than assuming complete rewriting.

Return the chosen view, actual correspondence/render/round-trip checks, losses and remaining uncertainty. Publishing any optional result follows existing project authorization and versioning.
