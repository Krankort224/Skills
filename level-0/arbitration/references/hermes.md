# Hermes specialist coordination

Use for a Hermes participant independently reachable by the user or another authorized participant. A minion here is an independently addressable participant with its own intake and return route. A child controlled inside one of those participants' execution contexts remains part of that participant's contribution, even if the interface exposes its handle or preserves its state. Addressability does not guarantee persistence, access to another session's material or permission to contact it.

## Accept a direct assignment

A specialist may receive the user's task directly. Establish the current remit from the actual assignment and governing grants. Identify the owner of this outcome, the owner of any wider result it feeds and the return point when those differ. The specialist can own the direct task and return it to the user even if a main agent owns other project work. Locate roles and verify access from current assignments and addresses.

Use the [common assignment contract](../SKILL.md#make-and-receive-a-bounded-assignment). If the task can be completed within the specialist's remit, do it directly. If it touches an adjacent area, identify the fact, artifact or decision needed and the owner who can supply it. Verify that contact, data sharing and the requested operation fit existing grants. Where any of these are missing, identify the exact gap and continue separable work.

## Consult an adjacent owner

Send the request to the adjacent specialist directly when the route and grants allow it. Include only the context needed, the precise question or bounded result, an accessible source revision, permitted effects, evidence expected and the return destination. Keep any confidential or unrelated context outside the request. Check the answer against its source and use it within the commissioning assignment.

For example, a compatibility specialist may ask the interface owner which fields a pinned contract guarantees. The interface owner returns a source citation or states the uncertainty. A factual consultation leaves the wider task with its owner and authorizes only the requested factual contribution within existing grants. A proposed interface patch, scope change or new expenditure needs its own authorization.

If a main agent owns a combined result, it can commission a specialist's bounded contribution and integrate it. A direct user task or permitted horizontal consultation can use its own route. Refer a genuinely reserved decision to the person or participant who owns it, with the evidence, options and consequences. Do not make a main agent a forwarding layer for routine requests.

## Preserve accountability at the boundary

Keep the specialist's requested work, effects, evidence and return attributable to that specialist. If a specialist uses permitted internal help, the specialist owns the result and any outstanding work. Account for queued work before reporting a result that depends on it. Establish an independent delivery route with evidence of actual addressability. Use only existing grants for spawning, settings, provider use and spending.

Verify receipt, result access or continuing availability only to the extent needed, using observable state in the actual interface. A sent request or saved identifier does not establish delivery, execution or persistence. If a required check cannot be obtained from an authorized non-author, return the gap. Apply the [interrupted assignment](../SKILL.md#recover-an-interrupted-assignment) contract when live state or write settlement is uncertain and the [readiness assessment](../operations/assess-readiness.md) when a combined result needs a decision.
